# SuchMusic 手环通讯（小米手环）

> 本功能为**可插拔**：不影响未使用手环的用户。默认关闭，只有用户在「设置 → 小米手环」显式开启后才建连。
> 本文档面向**上游原版**（`sunset5277/SuchMusic`，包名 `com.such.music.such_music`）的 PR 审阅者。

---

## 1. 这是什么

通过小米官方的 `xms-wearable-lib`（`com.xiaomi.xms.wearable.*`）建立「手机 App ↔ 小米手环快应用」
的通信通道，让手环可以**控制播放 / 查看歌曲 / 搜索 / 看歌词 / 切换播放模式**。

手机端新增两部分：

| 层 | 位置 | 作用 |
|---|---|---|
| 原生 Kotlin | `android/app/src/main/kotlin/com/such/music/such_music/band/` | 连接、分片编解码、信封路由、通道桥接 |
| Dart | `lib/services/band/` | 信封/协议、分片、连接门面、路由（命令落到**原版自己的**播放服务） |

**主逻辑在 Dart 侧**，Kotlin 只做「连接 + 收发 + 极薄的透传」，避免双份逻辑。

## 2. 协议摘要（与设计文档冻结值一致）

### 2.1 统一信封

```json
{ "v": 1, "id": "b-7fa1-0007", "type": "req", "method": "playback.next", "payload": {}, "ts": 1730000000000 }
```

| 字段 | 说明 |
|---|---|
| `v` | 协议主版本，会话内固定为协商值 |
| `id` | `{origin}-{bootId}-{seq}`，`origin ∈ {b,p,w}` |
| `type` | `req` / `res` / `evt` / `err` |
| `method` | 仅 `req` |
| `event` | 仅 `evt` |
| `payload` | 恒存在，可为 `{}` |
| `ts` | 毫秒时间戳（手机时钟为权威） |

### 2.2 方法清单（本 PR 已实现）

`sys.hello` · `sys.ping` · `state.get` · `song.info` ·
`playback.play` · `playback.pause` · `playback.toggle` · `playback.next` · `playback.prev` ·
`playback.seek` · `playback.setMode` · `queue.play` · `queue.clear` ·
`search.song` · `search.suggest` · `search.hot` · `lyric.window` · `cover.get` · `xfer.nack`

> `playback.setVolume` 返回 `E_UNSUPPORTED`（原版无独立音量控制，属 Phase 2）。

### 2.3 事件清单（本 PR 已实现）

`sys.hello_ack` · `sys.error` · `player.state` · `player.song` · `player.progress`（≤1 次/秒）·
`player.mode` · `player.queue` · `lyric.line` · `lyric.meta` · `xfer.chunk`

### 2.4 握手 / 版本 / 能力协商

1. 手环 `onopen` 后发 `sys.hello{role, proto:[int], caps:[str], fw, model, rpk}`；
2. 手机回 `sys.hello_ack{proto, caps, server, clock}`；
3. 会话版本 `V = max(band.proto ∩ phone.proto)`；交集为空 → 回 `err E_UNSUPPORTED` 并仅允许 `sys.*`；
4. 生效能力 `= band.caps ∩ phone.caps`；缺失能力时：手机收到该请求回 `E_UNSUPPORTED{missing}`，
   手机不发该事件。**原版能力集合不含 `volume`**（见 `kPhoneCaps`）。

### 2.5 分片（header → data → end）

| 约束 | 值 |
|---|---|
| 单包上限 `chunkMaxBytes` | **900 B** |
| 组装上限 `assembleMaxBytes` | **8192 B** |
| 校验 | 整包 `crc32`（IEEE / zlib 同款） |
| 文本字段 | `txt`（不额外 Base64） |
| 二进制字段 | `b64`（Base64） |
| 重传 | `xfer.nack{tid,seq}` |

超阈值的 `search.song` / `lyric.window` / `cover.get` 结果以 `xfer.chunk` 事件分片下发，
`res.payload` 返回 `{__chunked:true, tid, total, bytes, crc32}` 摘要。手环端组装校验 CRC32。

### 2.6 幂等

手机端对 `req.id` 维护 **LRU(64)**：收到重复 `id` **直接回放缓存响应、不重复执行** —— 保证
「重复点下一首不会跳过多首」。实现见 `band_router.dart` 的 `_dedupe`。

## 3. 接口差异清单（上游原版 vs 概念版）

> 本 PR **按上游原版的真实接口**实现，未照搬概念版。逐项核对如下：

| # | 差异点 | 概念版（`com.lightningteam.suchmusic`） | **上游原版（本 PR 目标，已实读）** | 本 PR 处理 |
|---|---|---|---|---|
| D1 | 播放模式枚举 | `PlayMode{loop,single,shuffle}` | **同名同值** `enum PlayMode { loop, single, shuffle }`（`audio_player_service.dart:17`） | 一一映射，无需改 |
| D2 | 播放器状态枚举 | `PlayerState{idle,loading,playing,paused,error}` | **同名同值** | 直接 `.name` |
| D3 | 播控方法 | `play/pause/resume/togglePlayPause/seek/playNext/playPrevious/playAtIndex/togglePlayMode/clearPlaylist` | **同名** `pause()/resume()/togglePlayPause()/seek(Duration)/playNext()/playPrevious()/playAtIndex(int)/clearPlaylist()` | 直接转发 |
| D4 | **设置播放模式** | 概念版可循环/直接设 | **仅有循环式** `togglePlayMode()`，**没有** `setPlayMode` | **上游新增** `setPlayMode(PlayMode)`（最小改动，见 §7） |
| D5 | 单例 | `AudioPlayerService()` 工厂单例 | **同款** `_instance` + `factory AudioPlayerService()` | 直接复用（与 handler 同源） |
| D6 | 状态流命名 | `onStateChanged/onPositionChanged/onDurationChanged/onLyricChanged/onLyricsChanged/onPlaylistChanged/onCurrentSongChanged/onPlayModeChanged` | **完全同名**（8 条） | 直接订阅 |
| D7 | MediaSession | `AudioPlayerHandler extends BaseAudioHandler` | **同款**，订阅同一 `AudioPlayerService()` 单例 | 桥接挂在 **service 层**，不动 handler |
| D8 | 歌曲模型字段 | `SongModel{id,name,artist,album,coverUrl,duration(ms),source,hash,albumId,albumAudioId,localUri}` | **只有** `SongModel{id,name,artist,album,coverUrl,duration(ms)}`；**无** `source`/`hash`/`albumId`/`localUri` | 协议 `source` **恒为 `"netease"`**；`durationMs` 直取 `duration`（毫秒） |
| D9 | 音源枚举 | `SongSource{netease,kugouStd,kugou,local}` + `SourceManager` | **无 `SongSource`、无 `SourceManager`**；仅网易云 | 不引入，`source="netease"` |
| D10 | 搜索入口 | `SourceManager().source.search(kw,{limit})` / `hotSearch()` / `searchSuggest(kw)` | `MusicApiService().search(keywords,{limit=30})` / **`getHotSearchKeys()`** / `searchSuggest(keywords)` | 适配器映射（注意 hot 方法名不同） |
| D11 | 歌词结构 | `LyricLine{timestamp,text}` + `currentLyricIndex` | **同款** `LyricLine{timestamp(Duration),text}` + `currentLyricIndex` getter | 切片读 `service.lyrics` |
| D12 | 音量 | 有 `setVolume` | **无** | `volume` 能力不声明；`setVolume` 回 `E_UNSUPPORTED` |
| D13 | 原生入口 | 概念版已有 `IslandBridge`/`SoundEffectBridge` 等 MethodChannel | **`MainActivity` 此前无任何 MethodChannel**（继承 `AudioServiceActivity`） | **从零新增**独立通道，不触碰既有原生 |
| D14 | 构建脚本 | AAR `flatDir` | `build.gradle.kts`（Kotlin DSL），无 `flatDir`/`dependencies` 块 | **条件式**引入 AAR（存在才加） |
| D15 | 包名 | `com.lightningteam.suchmusic` | `com.such.music.such_music` | 见 §5（**限制**） |

| 协议方法 | → 上游接口 |
|---|---|
| `playback.play` | 有歌 → `resume()`；无歌 → `togglePlayPause()` |

## 4. 启用真机通信（放置 AAR）

小米官方 SDK 带**专有许可**，**不随本仓库分发**。要启用真机通信：

1. 从官方渠道获取 `xms-wearable-lib`（v1.4 及以上）的 AAR；
2. 放到 `android/app/libs/`，文件名以 `xms-wearable-lib` 开头、以 `.aar` 结尾
   （例如 `android/app/libs/xms-wearable-lib_1.4_release.aar`）；
3. 重新执行 `flutter build apk`（或 IDE 运行）。

`android/app/build.gradle.kts` 会自动检测该 AAR 并加入依赖；**没有该文件时构建照常通过**，
手环功能在运行期自动降级为「不可用（Noop）」，其余功能完全不受影响。

> 手机上还需首次授予 `Permission.DEVICE_MANAGER`（由 SDK 触发系统授权弹窗）。

## 5. ⚠️ 包名 / 签名一致性（本 PR 的**核心限制**）

小米的 interconnect 通道**只对「包名 + 签名与手环快应用完全一致」的手机 App 开放**，否则通信被
**静默拒绝**。

- **本 App 包名**：`com.such.music.such_music`
- **手环快应用包名**：若直接沿用为概念版构建的快应用（包名 `com.lightningteam.suchmusic`），
  **无法与本 App 通信**。

因此，本 PR 在**不改手机端包名**的前提下，提供两种可选做法：

| 方案 | 做法 | 代价 |
|---|---|---|
| **方案 ①（推荐）** | 使用本仓库的手机 App 包名 / 签名**重新构建手环快应用**：把快应用 `manifest.json` 的 `package` 改为 `com.such.music.such_music`，并用**本 App 签名**重新签名（`sign/sign.pem` 由本 App 的 `.jks` 导出，须含私钥 + 证书） | 需重新构建 + 重新签名 `.rpk`，并重新侧载到手环 |
| **方案 ②** | **保持快应用包名不变**（`com.lightningteam.suchmusic`），本 PR 仅落地「协议 + 桥接」层，通信待后续决定是否统一包名 | 当前**无法真机互通**，仅代码就绪 |

> 本 PR 属于「协议 + 桥接」就绪，**未包含手环快应用源码**（在独立仓库 `Explore0416/SuchMusic-Band`）。
> 若上游接受本 PR，建议在合并说明中明确采用方案 ① 并同步快应用侧改动。

## 6. 真机验证步骤

1. 手环：安装与本 App **同包名 + 同签名**的 SuchMusic 快应用（`.rpk`），并确保手环与手机已配对。
2. 手机：安装启用了手环功能的 APK，打开「设置 → 小米手环 → 启用手环通讯」。
3. 首次会弹 `DEVICE_MANAGER` 授权，允许。
4. 手机播放一首歌 → 打开手环上的 SuchMusic：
   - 首页应显示当前歌名/艺人/进度；
   - 点 ▶/⏸、⏭、⏮ 应与手机同步；
   - 拖动进度条 → 手机 seek；
   - 搜索页点热搜词 → 返回结果 → 点某条 → 手机开始播放；
   - 播放模式页选「单曲循环」→ 手机 `PlayMode` 变为 `single`；
   - 歌词页显示当前行高亮 + 上下若干行。
5. 幂等验证：快速连点 ⏭ 5 次，应每次只切一首。
6. 断连验证：关闭手机蓝牙 3s 后恢复，手环应显示「未连接」→ 自动重连 → 重同步。

> 日志：手机端可用 `adb logcat -s BandConnection BandMessageRouter` 观察原生侧；
> Dart 侧 `BandService` / `BandRouter` 相关调试信息。

## 7. 对上游既有代码的最小改动

为支持手环，本 PR 对既有文件仅做**必要且克制**的改动：

| 文件 | 改动 | 原因 |
|---|---|---|
| `lib/services/audio_player_service.dart` | **新增** `setPlayMode(PlayMode)` 方法（可选式直接设模式） | 原版只有循环式 `togglePlayMode()`，无法「直接跳到目标模式」，手环模式页需要它。副作用与 `togglePlayMode` 保持一致 |
| `lib/main.dart` | 新增 **1 行** `unawaited(BandService().autoStart())` | 仅当用户开启过才建连，默认 no-op |
| `lib/screens/settings_page.dart` | 「其他」分组新增一行「小米手环」入口 | UI 入口，改动最小 |
| `android/app/src/main/kotlin/.../MainActivity.kt` | 新增 `configureFlutterEngine` 注册手环通道 | 原版此前无任何 MethodChannel，需注册新通道 |
| `android/app/build.gradle.kts` | 新增 `dependencies{}`，**条件式**引入 AAR | 无 AAR 时构建行为不变 |

其余全部为**新增文件**，不改动任何既有业务逻辑、不引入新依赖、不改代码风格。

## 8. 已知限制（如实说明）

1. **包名/签名一致性**：见 §5，这是能否真机互通的前提。
2. **SDK 未内置**：`xms-wearable-lib` 因许可原因不随仓库分发，需用户自行放置；无 AAR 时功能自动 Noop。
3. **反射契约待验证**：原生侧通过反射访问 SDK（`OnMessageReceivedListener` 的注册方法名等），
   不同 SDK 版本可能不同，已在代码中做好降级兜底；**需真机验证**。
4. **单包上限 900B 为保守值**：真实上限待真机二分验证；超大载荷走分片。
5. **无独立音量控制**：原版未暴露音量，`volume` 能力缺失，手环端应隐藏音量页（Phase 2）。
6. **歌词不整曲下发**：手环只存当前行 / 小窗口，避免占用存储。
7. **未包含手环快应用**：快应用在独立仓库，本 PR 仅手机端。

  band_protocol.dart       # 信封 / 错误码 / 版本·能力协商 / LRU（纯函数）
